# 候选质量补丁：事件交叠、商业内容、正文污染

适用：共享源码 PR #86 与 Bot 快照 PR #1 的 source-first 混合流水线。
不修改 `full_round`、生产 `news_rss_core` / `cleaner` 的行为；不改网站 CI、数据库、归档、邮件或现有部署。

## 三项确定规则

1. **同事件只保留一篇。** Pro 的 `event_key` 去重继续保留。Python 在排序答卷后，按已缓存原文检查相同具名赛事及年份、或较大比例的逐字内容交叠；保留排名较高的一篇，从后续排名补位。不因同为宝可梦就删除不同事件。周年文章若同时报道相同年份的宝可梦世界锦标赛，与那篇赛事报道合并为一个候选。
2. **广告嫌疑直接淘汰，不做备用。** 产品购物比较、Best/Top 产品清单、优惠码、购物指南，以及 affiliate、佣金、赞助/advertorial 声明，Python 在摘要与正文阶段排除。儿童广告监管、消费者保护等公共事务新闻，不因出现“广告”或“购物”字样自动淘汰。模板中的付费披露仍按疑似商业内容处理。
3. **TIME for Kids 被污染的提取结果直接淘汰。** shadow 专用抓取先对照页面相关文章区域。如果该区域真实摘要进入提取正文，记 `related_articles_in_extracted_body`，不把虚高字数计为合格，不抓图片，也不送模型。页面有相关文章区域但提取正文干净则允许；不是封禁整个来源。

## 处理顺序与恢复

- 抓取前：检查标题、RSS 摘要和 URL 的商业信号；拒绝原因进 source journal。
- 抓正文后：检查正文中的付费声明及 TFK 污染；再做字数/图片机械门禁。
- 排序前：缓存正文仍执行商业/已有 `skip_reason` 检查，避免进入另一栏绕过规则。
- Pro 排序后：Python 去内容交叠，`shortlist-<cat>-8.json.filtered` 记录删除 ID、原因及保留 ID；模型原答卷不改。
- 使用既有缺栏补采：若过滤后不足五篇，只从该栏下一冻结配置源补采，在固定五篇交接前重排。不是默认第二遍复核，不增加独立审核任务。
- 五篇已交给 Grok、或已接受的答卷不追溯改写。建议新目录验证本次补丁。

## 核验与限制

- Python 3.10 回归涵盖商业正/反例、污染与干净 DOM、跳过图片/合格计数、不同模型 event_key、不同年份/不同赛事、同品牌不同事件、下一备用稿递补且不增加模型调用。
- 增加真实样式回归：摘要省略发布日期时，从缓存原文取年份；作家访谈不因相关文章提到宝可梦而被判为赛事重复。
- 对上一轮真实缓存离线复核两篇宝可梦；对真实 TFK 两页只读验证污染拒绝。未新增模型调用或发布。
- Python 赛事识别仅作确定性兜底，不声称覆盖全部语义重复；Pro 仍负责七天同栏历史与一般事件判断。广告规则是保守嫌疑过滤，不证明出版方收取广告费。TFK 拒绝可能减少合格数，应继续抓其他来源，而不是放宽污染门禁凑数。
- 本次不改变冻结的采集数量、历史或来源配置，也不把临时 25 条 Fun 实验写成生产配置。
